## 2. 编译项目

### 2.1 分步编译（推荐，便于排查错误）

```bash
cd ~/go1_ws
source /opt/ros/humble/setup.bash

```bash
cd ~/go1_ws
source /opt/ros/humble/setup.bash

source install/setup.bash
```

> 如果内存不足，使用 `colcon build --parallel-workers 2` 限制并行数。

## 3. 常见编译错误排查

### 3.1 FAST-LIO 编译错误

**错误**: `fatal error: nav_msgs/msg/odometry.hpp: No such file or directory`
```
原因: nav_msgs 头文件未找到
解决: sudo apt-get install -y ros-humble-nav-msgs
```

**错误**: `error: 'tf2_ros' was not declared` 或找不到 `tf2_ros::TransformBroadcaster`
```
原因: FAST-LIO package.xml 缺少 tf2_ros 依赖（但它通过 nav_msgs 间接包含）
解决: 确认 find_package(tf2_ros) 不是必需的，因为头文件通过其他包传递
      如果确实报错，在 CMakeLists.txt 中添加：
        find_package(tf2_ros REQUIRED)
      并在 dependencies 列表中添加 tf2_ros
```

**错误**: `Eigen 相关的模板实例化错误`（密密麻麻的模板报错）
```
原因: 里程计约束代码中的矩阵维度可能不匹配
解决: 检查 apply_odom_position_constraint() 中：
      - H 矩阵维度应为 3x23（不是 3x24，因为 DOF=23）
      - P 矩阵维度应为 23x23
      - K 矩阵维度应为 23x3
      - dx 维度应为 23x1
```

**错误**: `boxplus is not a member of state_ikfom`（可能性低但需注意）
```
原因: boxplus 是 MTK 库的方法，在 vect3、SO3、S2 类型上定义
解决: 确认 state_ikfom 的 boxplus 方法签名为 
      void boxplus(const Eigen::Matrix<double, DOF, 1>& dx)
      其中 DOF=23
```

### 3.2 TEB 编译错误

**错误**: `Could not find a package configuration file provided by "g2o"`
```
解决: sudo apt-get install -y ros-humble-libg2o
```

**错误**: `cannot find -lg2o_core`（链接错误）
```
解决: 确认 libg2o 安装路径：
      dpkg -L ros-humble-libg2o | grep .so
      如果路径不在默认搜索路径中，可能需要设置 LD_LIBRARY_PATH
```

**错误**: TEB 在 ARM64 上编译失败
```
备选方案: 如果 TEB 实在无法编译，可回退使用 MPPI 控制器
修改 go1_nav_params.yaml 中的 controller_plugins:
  FollowPath:
    plugin: "nav2_mppi_controller::MPPIController"
    # ... MPPI 参数
```

### 3.3 costmap_converter 编译错误

**错误**: `Class CostmapToDynamicObstacles not found`
```
解决: 确认编译顺序：costmap_converter_msgs → costmap_converter
      colcon build --packages-select costmap_converter_msgs
      source install/setup.bash
      colcon build --packages-select costmap_converter
```

### 3.4 go1_bringup 相关

**错误**: `Package 'robot_localization' not found`
```
解决: sudo apt-get install -y ros-humble-robot-localization
```

## 6. 实验三：里程计融合约束增强 SLAM

> **目标**: 开启里程计位置约束，与基线对比，验证几何退化场景下的漂移抑制

### 6.1 开启里程计约束

编辑 `~/go1_ws/src/FAST_LIO/config/mid360.yaml`：
```yaml
odom_constraint:
    enable: true     # ← 开启
    odom_topic: "/odometry/filtered"
    degradation_feat_threshold: 50
    degradation_residual_threshold: 0.3
    odom_noise_normal: 10.0
    odom_noise_degraded: 0.1
```

重编译：
```bash
cd ~/go1_ws && colcon build --packages-select fast_lio --symlink-install
source install/setup.bash
```

### 6.2 启动完整系统

```bash
ros2 launch go1_bringup go1_base.launch.py
```

此命令会同时启动：
| 组件 | 功能 | 输出话题 |
|------|------|----------|
| unitree_ros | Go1 驱动 | `/odom`, `/imu`, `/cmd_vel` |
| livox_ros_driver2 | MID360 驱动 | `/livox/lidar`, `/livox/imu` |
| static_transform_publisher (×2) | TF 桥接 | TF: `body→livox_frame`, `unitree_base→body` |
| FAST-LIO2 | LiDAR-IMU 里程计 | `/Odometry`, `/cloud_registered`, TF: `camera_init→body` |
| robot_localization (ekf_node) | 融合里程计 | `/odometry/filtered` |
| pointcloud_to_laserscan | 3D→2D | `/scan` |

### 6.3 验证融合里程计

```bash
# 检查 robot_localization 是否正常输出
ros2 topic hz /odometry/filtered
# 预期: ~50 Hz

# 查看融合里程计数据
ros2 topic echo /odometry/filtered --once

# 检查 FAST-LIO2 是否收到融合里程计
# 查看日志应有: "Odom constraint ENABLED, topic: /odometry/filtered"
```

> **⚠️ 潜在问题：`/odometry/filtered` 无输出**
> 
> 原因1：robot_localization 找不到 TF `unitree_odom → body`
> ```bash
> # 检查 TF 树是否包含 unitree_base → body 的桥接
> ros2 run tf2_ros tf2_echo unitree_odom body
> ```
> 如果报错 "Could not find a connection"，说明静态 TF 发布有问题。检查：
> - `unitree_base_to_body_tf` 节点是否启动
> - unitree_ros 的 `odom_child_frame_id` 是否确实是 `unitree_base`
>
> 原因2：robot_localization 配置中 `base_link_frame` 与实际帧名不匹配
> ```bash
> # 查看 robot_localization 日志
> ros2 node list | grep ekf
> ros2 node info /ekf_filter_node
> ```
>
> 原因3：`/odom` 话题的 frame_id 不是 `unitree_odom`
> ```bash
> ros2 topic echo /odom --field header.frame_id --once
> # 应该是: unitree_odom
> ```

### 6.4 观察退化检测

在走廊等特征退化场景中行走时，观察终端输出：
```
[WARN] Geometric degradation detected! feat_num=32, res_mean=0.452. Applying odom constraint with high weight.
```

如果在开阔环境也频繁触发退化告警，说明阈值太松，需要调整（见 §11）。

### 6.5 改进版数据采集

使用与基线实验 **完全相同的路线** 行走，录制数据：

```bash
ros2 bag record /Odometry /odom /imu /odometry/filtered /cloud_registered /scan \
    -o ~/go1_ws/bags/improved_run1
```

## 7. 实验四：SLAM 建图（slam_toolbox）

> **目标**: 使用 slam_toolbox 生成 2D 占据栅格地图，供后续导航使用

### 7.1 启动建图

```bash
ros2 launch go1_bringup go1_mapping.launch.py
```

这会启动 `go1_base.launch.py`（底层驱动 + FAST-LIO2 + 点云转换） + slam_toolbox。

### 7.2 RViz 可视化建图过程

```bash
rviz2
```

在 RViz 中：
1. **Fixed Frame** 设为 `map`
2. 添加 **Map** 显示，话题选择 `/map`
3. 添加 **LaserScan** 显示，话题选择 `/scan`
4. 添加 **TF** 显示
5. 添加 **RobotModel**（如果有 URDF）或 **Axes** 在 `body` 帧

### 7.3 遥控机器人建图

用遥控器控制机器人 **缓慢地** 遍历整个实验场地：
- 线速度控制在 0.2-0.3 m/s
- 每到一个区域停留 2-3 秒让 slam_toolbox 优化
- 尽量走闭环路线（回到出发点）以触发回环检测

### 7.4 保存地图

建图完成后，保存地图：

```bash
# 方法1: 使用 map_saver
ros2 run nav2_map_server map_saver_cli -f ~/go1_ws/src/go1_bringup/maps/my_lab

# 方法2: 使用 slam_toolbox 的服务
ros2 service call /slam_toolbox/save_map slam_toolbox/srv/SaveMap \
  "{name: {data: '/home/ziggy/go1_ws/src/go1_bringup/maps/my_lab'}}"
```

这会生成两个文件：
- `my_lab.yaml` — 地图元数据
- `my_lab.pgm` — 地图图像

### 7.5 验证地图

```bash
# 查看生成的地图文件
ls -la ~/go1_ws/src/go1_bringup/maps/
# 应该有: my_lab.yaml, my_lab.pgm

# 用图片查看器打开 pgm 文件确认地图质量
eog ~/go1_ws/src/go1_bringup/maps/my_lab.pgm
# 或
display ~/go1_ws/src/go1_bringup/maps/my_lab.pgm
```

> **⚠️ 如果地图质量差（扭曲、重影）**：
> - 建图速度太快 → 放慢遥控速度
> - pointcloud_to_laserscan 参数不当 → 调整 `min_height` / `max_height`
> - slam_toolbox 闭环参数太松 → 调整 `loop_match_minimum_response_coarse`

### 7.6 重编译以包含地图文件

```bash
cd ~/go1_ws
colcon build --packages-select go1_bringup
source install/setup.bash
```

## 8. 实验五：Nav2 自主导航

> **目标**: 使用 Nav2 在已建地图上进行自主导航（AMCL 定位 + A* 全局规划 + TEB 局部规划）

### 8.1 前提条件

- [x] 已完成建图并保存地图文件（`my_lab.yaml` + `my_lab.pgm`）

### 9.5 评估指标说明

| 指标 | 含义 | 期望 |
|------|------|------|
| **APE (RMSE)** | 绝对位姿误差均方根 | 改进版 < 基线 |
| **APE (max)** | 绝对位姿最大误差 | 改进版 < 基线（尤其在退化段） |
| **RPE (RMSE)** | 每段相对位姿误差 | 衡量局部一致性 |
| **闭环漂移** | 返回起点时的位置偏差 | 目测即可 |

   ```

2. **对比改进版和基线的一致性**：直接用 evo_ape 将其中一个作为参考

## 12. 已知问题与 Bug 排查

### 12.1 TF 树冲突（最常见问题）

**症状**: 终端大量警告 `Warning: TF_REPEATED_DATA` 或 `Could not find a connection between...`

**排查步骤**：
```bash
# 1. 查看完整 TF 树
ros2 run tf2_tools view_frames
# 生成 frames.pdf，检查是否有重复的父子关系

# 2. 查看特定帧的变换
ros2 run tf2_ros tf2_echo map camera_init
ros2 run tf2_ros tf2_echo camera_init body
ros2 run tf2_ros tf2_echo unitree_odom unitree_base
ros2 run tf2_ros tf2_echo unitree_base body
```

**预期 TF 树**:
```
map → camera_init → body → livox_frame
            ↑
      (AMCL 发布, 仅导航时)
      
camera_init → body
      ↑
   (FAST-LIO2 发布)

unitree_odom → unitree_base → body
      ↑               ↑
 (unitree_ros)  (静态TF桥接)
```

**常见冲突**:
- `robot_localization` 的 `publish_tf` 必须为 `false`（已配置）
- `unitree_ros` 会发布 `unitree_odom → unitree_base` 的 TF
- `body → livox_frame` 是静态 TF

### 12.2 时间戳不同步

**症状**: `Lookup would require extrapolation into the future` 或 `Could not get transform`

**排查**:
```bash
# 查看各传感器时间戳是否接近
ros2 topic echo /odom --field header.stamp --once
ros2 topic echo /livox/lidar --field header.stamp --once
ros2 topic echo /imu --field header.stamp --once
```

**解决**:
1. 确认所有节点使用系统时钟（非仿真时间）
2. 增大 `transform_tolerance`：
   - `go1_nav_params.yaml` 中的 `transform_tolerance: 2.0`
   - `pointcloud_to_laserscan_params.yaml` 中的 `transform_tolerance: 0.5`

### 12.3 robot_localization 不融合数据

**症状**: `/odometry/filtered` 话题有输出但值全为 0 或不变

**排查**:
```bash
# 查看 robot_localization 的诊断
ros2 topic echo /diagnostics

# 查看 robot_localization 节点日志
# 应该有类似: "Slow data ..." 或 "Stopped data ..." 的警告
```

**常见原因**:
1. `/odom` 的 `header.frame_id` 与配置中的 `odom_frame` 不匹配
2. `/imu` 的 `header.frame_id` 与配置中的帧不匹配
3. TF 树中缺少 `unitree_base → body` 的桥接

### 12.4 FAST-LIO2 初始化失败

**症状**: 启动后终端一直输出 "No point, skip this scan!"

**排查**:
```bash
# 检查 LiDAR 数据是否正常
ros2 topic hz /livox/lidar
ros2 topic echo /livox/lidar --once

# 检查 IMU 数据
ros2 topic hz /livox/imu
```

**解决**:
1. 确认 MID360 已通电并正常旋转
2. 检查 `mid360.yaml` 中 `lid_topic` 和 `imu_topic` 是否正确
3. FAST-LIO2 启动后需要约 2 秒的 IMU 初始化时间，保持静止

### 12.5 Go1 的 Z 轴颠簸影响

**症状**: 点云地图有明显的垂直方向分层/模糊

**原因**: Go1 行走时的高频 Z 轴颠簸（2-3cm, ~4Hz）

**缓解措施**:
1. `ekf_odom_fusion.yaml` 中已禁用 Z 轴融合（`odom0_config` Z=false）
2. FAST-LIO2 的 IMU 预积分会部分补偿，但仍有残余
3. `pointcloud_to_laserscan` 使用宽松的 `min_height`/`max_height` 容忍抖动

### 12.6 Jetson AGX Orin 性能问题

**症状**: 节点启动缓慢，处理延迟大

**优化**:
```bash
# 切换到最大性能模式
sudo nvpmodel -m 0
sudo jetson_clocks

# 查看当前功耗模式
nvpmodel -q
```

**降低计算负载的参数调整**:
- FAST-LIO: `point_filter_num: 4`（当前=3，更大=采样更少）
- FAST-LIO: `filter_size_surf: 0.8`（当前=0.5）
- slam_toolbox: `map_update_interval: 10.0`（当前=5.0）
- controller_server: `controller_frequency: 5.0`（当前=10.0）

    │ (FAST-LIO2 发布,                           │ (静态TF桥接,
    │  ~10Hz)                                    │  go1_base.launch.py)
    ↓                                            ↓
  [body] ←───────────────────────────────── [body]
    │         (同一帧, 通过静态TF连接)
    │
    │ (静态TF, go1_base.launch.py,
    │  x=0.1, z=0.15)
    ↓
  [livox_frame]


  数据流:
  ┌───────────────────────────────────────────────────────────────────────┐
  │ LiDAR (/livox/lidar) ──→ FAST-LIO2 ──→ /Odometry, /cloud_registered│
  │ IMU   (/livox/imu)   ──→            ──→ TF: camera_init → body      │
  │                                                                       │

  │ /scan               ──→ Nav2 (AMCL + A* + TEB)  ──→ /cmd_vel        │
  └───────────────────────────────────────────────────────────────────────┘

## 附录 C：紧急回退方案

如果某个组件无法正常工作，以下是回退方案：

### TEB 无法编译 → 回退到 RPP 控制器

修改 `go1_nav_params.yaml`：
```yaml
FollowPath:
  plugin: "nav2_regulated_pure_pursuit_controller::RegulatedPurePursuitController"
  desired_linear_vel: 0.3
  lookahead_dist: 0.6
  min_lookahead_dist: 0.3
  max_lookahead_dist: 0.9
  lookahead_time: 1.5
  rotate_to_heading_angular_vel: 1.0
  transform_tolerance: 0.1
```
> 注意: RPP 不支持全向运动，Go1 只能前进和原地旋转

### robot_localization 无法安装 → 禁用里程计约束

修改 `mid360.yaml`：
```yaml
odom_constraint:
    enable: false
```

从 `go1_base.launch.py` 中移除 `ekf_node` 和 `unitree_base_to_body_tf`。

### slam_toolbox 地图质量差 → 使用 FAST-LIO2 PCD 手动建图

```bash
# FAST-LIO2 会保存 PCD 点云
# 启动后会在 FAST_LIO/PCD/ 下生成 scans.pcd
# 也可以通过服务触发保存:
ros2 service call /map_save std_srvs/srv/Trigger "{}"

# 使用 CloudCompare 或 pcl_viewer 查看点云
pcl_viewer ~/go1_ws/src/FAST_LIO/PCD/scans.pcd

# 使用 octomap 将 3D 点云转为 2D 栅格地图
sudo apt-get install -y ros-humble-octomap ros-humble-octomap-server
# 需要自行编写转换脚本
```

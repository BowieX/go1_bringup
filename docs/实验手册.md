## 1. 环境准备与依赖安装

```bash
# 确认 colcon 构建工具
```

```bash
sudo apt-get install -y ros-humble-pointcloud-to-laserscan

# tf2 工具
sudo apt-get install -y ros-humble-tf2-ros ros-humble-tf2-tools

# PCL 和 Eigen（FAST-LIO 编译需要）
sudo apt-get install -y libpcl-dev libeigen3-dev

# OpenMP（并行计算，可选）
sudo apt-get install -y libomp-dev
```

### 1.3 安装 Python 评估工具

```bash

pip3 install evo --upgrade

# Jetson 上需同时升级 scipy，否则 evo_ape 会报 numpy 二进制不兼容错误
pip3 install "scipy>=1.11"

# 验证安装
evo_ape --help
```

> **注意**: 如果 `pip3 install evo` 失败（ARM64 架构），可尝试：

> **注意**: 如果 `evo_ape --help` 报 `ValueError: numpy.dtype size changed`，
> 原因是系统 scipy 与 pip 安装的 NumPy 2.x 二进制不兼容，运行以下命令修复：
> ```bash
> pip3 install "scipy>=1.11"

## 2. 编译项目

### 2.1 分步编译（推荐，便于排查错误）

```bash
cd ~/go1_ws
source /opt/ros/humble/setup.bash

# 第一步：编译消息包（无外部依赖）
colcon build --packages-select unitree_ros livox_ros_driver2 fast_lio
source install/setup.bash

# 第二步：编译 costmap_converter（TEB 的依赖）
colcon build --packages-select costmap_converter_msgs costmap_converter
source install/setup.bash

# 第三步：编译 TEB 局部规划器
colcon build --packages-select teb_msgs teb_local_planner
source install/setup.bash

# 第四步：编译 go1_bringup（依赖以上所有包）
colcon build --packages-select go1_bringup
source install/setup.bash
```

### 2.2 一键全量编译

```bash
cd ~/go1_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/setup.bash
```

> **提示**: 在 Jetson AGX Orin 上首次编译 FAST-LIO 可能需要 5-10 分钟。
> 如果内存不足，使用 `colcon build --parallel-workers 2` 限制并行数。

### 2.3 编译后环境设置

每次打开新终端都需要执行：
```bash
source /opt/ros/humble/setup.bash
source ~/go1_ws/install/setup.bash
```

建议将以下内容加入 `~/.bashrc`：
```bash
echo "source ~/go1_ws/install/setup.bash" >> ~/.bashrc
```

## 3. 常见编译错误排查

### 3.1 FAST-LIO 编译错误

**错误**: `fatal error: nav_msgs/msg/odometry.hpp: No such file or directory`
```
原因: nav_msgs 头文件未找到
解决: sudo apt-get install -y ros-humble-nav-msgs
```

**错误**: `Eigen 相关的模板实例化错误`（密密麻麻的模板报错）
```
原因: 里程计约束代码中的矩阵维度可能不匹配
解决: 检查 apply_odom_position_constraint() 中：
      - H 矩阵维度应为 3x23（不是 3x24，因为 DOF=23）
      - P 矩阵维度应为 23x23
      - K 矩阵维度应为 23x3
      - dx 维度应为 23x1
```

### 3.2 TEB 编译错误

**错误**: `Could not find a package configuration file provided by "g2o"`
```
解决: sudo apt-get install -y ros-humble-libg2o
```

**错误**: TEB 在 ARM64 上编译失败
```
备选方案: 如果 TEB 实在无法编译，可回退使用 RPP 控制器
修改 go1_nav_params.yaml 中的 controller_plugins:
  FollowPath:
    plugin: "nav2_regulated_pure_pursuit_controller::RegulatedPurePursuitController"
    desired_linear_vel: 0.3
    lookahead_dist: 0.6
    min_lookahead_dist: 0.3
    max_lookahead_dist: 0.9
    lookahead_time: 1.5
    rotate_to_heading_angular_vel: 1.0
    transform_tolerance: 0.1
    use_velocity_scaled_lookahead_dist: false
    min_approach_linear_velocity: 0.05
    approach_velocity_scaling_dist: 0.6
    use_collision_detection: true
    max_allowed_time_to_collision_up_to_carrot: 1.0
    use_regulated_linear_velocity_scaling: true
    use_fixed_curvature_lookahead: false
    curvature_lookahead_dist: 0.25
    regulated_linear_scaling_min_radius: 0.9
    regulated_linear_scaling_min_speed: 0.25
    allow_reversing: false
    max_robot_pose_search_dist: 10.0
```

### 3.3 go1_bringup 相关

**错误**: `Package 'robot_localization' not found`
```
解决方案A: sudo apt-get install -y ros-humble-robot-localization
解决方案B: 使用 use_odom_fusion:=false 参数跳过该依赖：
  ros2 launch go1_bringup go1_base.launch.py use_odom_fusion:=false
```

## 5. 实验二：SLAM 建图（slam_toolbox）

> **目标**: 使用 slam_toolbox 生成 2D 占据栅格地图，供后续导航使用  
> **前提**: 实验一硬件验证通过

### 5.1 启动建图

```bash
# 基础导航 Demo 不需要里程计融合，使用 use_odom_fusion:=false
ros2 launch go1_bringup go1_mapping.launch.py use_odom_fusion:=false
```

这会启动：`unitree_ros` + `livox_driver`（MID-360S）+ `FAST-LIO2`（无odom约束）+ `pointcloud_to_laserscan` + `slam_toolbox`

> **注意**: 如果机器狗未开机，`unitree_driver` 节点会报错退出（`CONNECTION IS NOT AVAILABLE`），
> 但这**不影响**建图功能。LiDAR → FAST-LIO → pointcloud_to_laserscan → slam_toolbox 的数据链路
> 完全独立于机器狗驱动，建图仍然可以正常进行（需要手持/推车携带 LiDAR 遍历场地）。
>
> FAST-LIO2 启动后的前 2-3 秒会输出 `No point, skip this scan!` 警告，这是 IMU 初始化的正常现象，
> 初始化完成后会自动开始处理点云数据。

### 5.2 RViz 可视化建图过程

```bash
rviz2
```

在 RViz 中：
1. **Fixed Frame** 设为 `map`
2. 添加 **Map** 显示，话题选择 `/map`
3. 添加 **LaserScan** 显示，话题选择 `/scan`
4. 添加 **TF** 显示

### 5.3 验证建图数据链路

启动建图后，在新终端中验证各级话题是否正常：
```bash
source ~/go1_ws/install/setup.bash

# 查看所有话题（应包含 /cloud_registered, /scan, /map 等）
ros2 topic list

# FAST-LIO2 输出 (~10Hz)
ros2 topic hz /cloud_registered
ros2 topic hz /Odometry

# 2D 激光扫描 (~10Hz)
ros2 topic hz /scan

# 地图话题（需要有运动后才会持续更新）
ros2 topic info /map
```

预期输出：
- `/cloud_registered`: ~10 Hz（FAST-LIO2 去畸变点云）
- `/Odometry`: ~10 Hz（FAST-LIO2 位姿估计）
- `/scan`: ~10 Hz（3D→2D 转换后的激光扫描）
- `/map`: `nav_msgs/msg/OccupancyGrid`（slam_toolbox 地图，有运动后开始更新）

### 5.4 遥控机器人建图

用遥控器控制机器人 **缓慢地** 遍历整个实验场地：
- 线速度控制在 0.2-0.3 m/s
- 每到一个区域停留 2-3 秒让 slam_toolbox 优化
- 尽量走闭环路线（回到出发点）以触发回环检测

### 5.5 保存地图

建图完成后，保存地图：

```bash
# 使用 map_saver（确保建图 launch 仍在运行）
ros2 run nav2_map_server map_saver_cli -f ~/go1_ws/src/go1_bringup/maps/my_lab
```

> **如果 map_saver 超时失败**，可能是 `/map` 话题尚未发布（LiDAR 未移动过）。
> 可以添加超时参数重试：
> ```bash
> ros2 run nav2_map_server map_saver_cli -f ~/go1_ws/src/go1_bringup/maps/my_lab \
>     --ros-args -p save_map_timeout:=10.0
> ```

这会生成两个文件：
- `my_lab.yaml` — 地图元数据（分辨率、原点等）
- `my_lab.pgm` — 地图图像（PGM 格式灰度图）

### 5.6 验证地图

```bash
# 查看生成的地图文件
ls -la ~/go1_ws/src/go1_bringup/maps/
# 应该有: my_lab.yaml, my_lab.pgm

# 查看地图元数据
cat ~/go1_ws/src/go1_bringup/maps/my_lab.yaml
# 应输出类似:
#   image: my_lab.pgm
#   resolution: 0.05
#   origin: [-14.1, -7.58, 0]
#   ...
```

> **如果地图质量差（扭曲、重影）**：
> - 建图速度太快 -> 放慢遥控速度
> - pointcloud_to_laserscan 参数不当 -> 调整 `min_height` / `max_height`
> - slam_toolbox 闭环参数太松 -> 调整 `loop_match_minimum_response_coarse`

### 5.7 重编译以包含地图文件

```bash
cd ~/go1_ws
colcon build --packages-select go1_bringup
source install/setup.bash
```

### 6.3 初始化定位（关键步骤！）

1. 在 RViz 工具栏点击 **"2D Pose Estimate"**
2. 在地图上点击机器人 **当前实际位置**，拖动箭头指向 **当前朝向**
3. AMCL 粒子会收敛，直到机器人位置与地图匹配

> **如果 AMCL 定位不收敛**：
> - 初始位姿估计偏差太大 -> 重新设置，尽量精确

4. 机器人开始自主行走

### 6.6 常见导航问题

**问题：导航一开始就报 "Failed to get a plan"**
```
原因：全局代价地图未更新，或 AMCL 定位不准
解决：
  1. 重新发送 2D Pose Estimate
  2. 检查 /scan 话题是否有数据
  3. 确认 global_costmap 的 global_frame 是 "map"
```

**问题：TEB 控制器报 "No valid cmd_vel"**
```
原因：TEB 找不到可行轨迹（参数可能过于保守）
解决：
  1. 增大 max_vel_x 和 max_vel_theta
  2. 减小 min_obstacle_dist
  3. 检查 local_costmap 是否正确感知障碍物
```

**问题：机器人原地旋转不前进**
```
原因：TEB 的全向配置可能有问题
解决：
  确认 go1_nav_params.yaml 中:
    holonomic_robot: true
    weight_kinematics_nh: 0.0
    max_vel_y: 0.3  (必须 > 0)
```

**问题：Plugin "teb_local_planner::TebLocalPlannerROS" not found**
```
原因：TEB 未编译成功或未正确安装
解决：
  1. colcon build --packages-select teb_local_planner
  2. source install/setup.bash
  3. ros2 plugin list | grep teb （确认插件已注册）
```

## 7. 实验四：SLAM 消融实验（足端里程计融合验证）

> **目标**: 通过 rosbag 离线回放，在完全相同的传感器输入下，对比加入/不加入足端里程计融合对 SLAM 精度的影响  
> **前提**: 实验一硬件验证通过

### 7.1 消融实验方法论

**为什么用 rosbag 离线回放？**

| 方案 | 优势 | 劣势 |
|------|------|------|
| 在线两次实跑 | 简单 | 无法保证路线完全一致，不公平 |
| **rosbag 离线回放** | 完全相同的输入数据，严格可复现 | 需要 `use_sim_time` 配置 |
| 导航层消融 | 验证端到端效果 | 变量太多，不适合单一因子消融 |

## 8. 实验五：SLAM 轨迹精度评估（evo）

> **目标**: 使用 evo 工具详细分析消融实验结果

### 8.1 评估指标说明

| 指标 | 含义 | 论文用途 |
|------|------|----------|
| **闭环漂移** | 回到起点时的位置误差 (m) | **主指标**，直观，不需要 ground truth |
| **APE RMSE** | 绝对位姿误差均方根 (m) | 整体轨迹偏差 |
| **APE Max** | 绝对位姿最大误差 (m) | 退化段最大漂移 |
| **RPE RMSE** | 每段相对位姿误差 (m) | 局部一致性 |

### 8.2 手动使用 evo 命令（更灵活）

```bash
# 1. 绘制两条轨迹的俯视图对比
evo_traj tum \
    ~/go1_ws/trajectories/traj_fastlio_baseline.txt \
    ~/go1_ws/trajectories/traj_fastlio_improved.txt \
    -p --plot_mode xz

# 2. 计算两条轨迹的 APE (改进版相对于基线的偏差)
evo_ape tum \
    ~/go1_ws/trajectories/traj_fastlio_baseline.txt \
    ~/go1_ws/trajectories/traj_fastlio_improved.txt \
    -vap --plot_mode xz

# 3. 计算 RPE（每1米的相对误差）
evo_rpe tum \
    ~/go1_ws/trajectories/traj_fastlio_baseline.txt \
    ~/go1_ws/trajectories/traj_fastlio_improved.txt \
    -va --delta 1 --delta_unit m

# 4. 如果有 ground truth，计算绝对精度
evo_ape tum ground_truth.txt traj_fastlio_baseline.txt -vap --plot_mode xz
evo_ape tum ground_truth.txt traj_fastlio_improved.txt -vap --plot_mode xz
```

### 8.3 无 Ground Truth 时的替代方案

如果没有外部定位系统（OptiTrack/Vicon），可以使用以下方法：

1. **闭环漂移法**：机器人走闭环回到起点，检查终点和起点坐标差
   ```bash
   # 查看 TUM 文件首尾几行
   head -1 traj_fastlio.txt
   tail -1 traj_fastlio.txt
   # 对比 x, y 值的差异即为闭环漂移
   ```

2. **对比基线和改进版的一致性**：直接用 evo_ape 将其中一个作为参考

3. **手动测量法**：用卷尺在实验场地标记几个参考点坐标，与轨迹中的对应时刻坐标对比

### 8.4 论文图表建议

需要准备的图表：
1. **轨迹俯视对比图**（evo_traj，基线蓝色 vs 改进版红色）
2. **APE 沿轨迹热力图**（evo_ape --plot，显示退化段误差飙升位置）

## 11. 已知问题与 Bug 排查

### 11.1 TF 树冲突（最常见问题）

**症状**: 终端大量警告 `Warning: TF_REPEATED_DATA` 或 `Could not find a connection between...`

**排查步骤**：
```bash
# 1. 查看完整 TF 树
ros2 run tf2_tools view_frames
# 生成 frames.pdf，检查是否有重复的父子关系

# 2. 查看特定帧的变换
ros2 run tf2_ros tf2_echo map camera_init
ros2 run tf2_ros tf2_echo camera_init body
```

**常见冲突**:
- `robot_localization` 的 `publish_tf` 必须为 `false`（已配置）
- 使用 `use_odom_fusion:=false` 可完全规避融合相关的 TF 问题

### 11.2 时间戳不同步

**症状**: `Lookup would require extrapolation into the future`

**排查**:
```bash
# 查看各传感器时间戳是否接近
ros2 topic echo /odom --field header.stamp --once
ros2 topic echo /livox/lidar --field header.stamp --once
```

**解决**: 增大 `transform_tolerance`

### 11.3 FAST-LIO2 初始化失败

**症状**: 启动后终端一直输出 "No point, skip this scan!"

**解决**:
1. 确认 MID-360S 已通电并成功连接（检查网线/IP `192.168.1.135`）
2. 确认使用了正确的启动脚本 `msg_MID360s_launch.py`（不是 `msg_MID360_launch.py`）
3. 检查 `mid360.yaml` 中 `lid_topic` 和 `imu_topic` 是否正确（默认 `/livox/lidar` 和 `/livox/imu`）
4. FAST-LIO2 启动后前 2-3 秒输出此警告是**正常现象**（IMU 初始化），
   初始化完成后会输出 `IMU Initial Done` 并开始处理点云
5. 如果持续输出（超过 5 秒），检查 `/livox/lidar` 话题是否有数据：
   ```bash
   ros2 topic hz /livox/lidar
   ```

### 11.4 rosbag 回放相关问题

**症状**: 回放时 FAST-LIO2 不输出数据

**排查**:
```bash
# 确认 bag 包含所需话题
ros2 bag info ~/go1_ws/bags/degradation_exp1

# 确认使用了 --clock 和 --topics 参数
ros2 bag play <bag> --clock --topics /livox/lidar /livox/imu /odom /imu

# 确认 FAST-LIO2 使用了 use_sim_time
ros2 param get /fastlio_mapping use_sim_time
```

**症状**: `/odometry/filtered` 无输出（fusion 模式回放）

**排查**:
```bash
# 确认 robot_localization 使用了 use_sim_time
ros2 param get /ekf_filter_node use_sim_time

# 确认 /odom 和 /imu 话题有数据
ros2 topic hz /odom
ros2 topic hz /imu
```

### 11.5 Jetson AGX Orin 性能问题

**症状**: 节点启动缓慢，处理延迟大

**优化**:
```bash
# 切换到最大性能模式
sudo nvpmodel -m 0
sudo jetson_clocks
```

## 附录 C：紧急回退方案

### TEB 无法编译 -> 回退到 RPP 控制器

修改 `go1_nav_params.yaml`：
```yaml
FollowPath:
  plugin: "nav2_regulated_pure_pursuit_controller::RegulatedPurePursuitController"
  desired_linear_vel: 0.3
  lookahead_dist: 0.6
  min_lookahead_dist: 0.3
  max_lookahead_dist: 0.9
  lookahead_time: 1.5
  rotate_to_heading_angular_vel: 1.0
  transform_tolerance: 0.1
```
> 注意: RPP 不支持全向运动，Go1 只能前进和原地旋转

### robot_localization 无法安装 -> 使用基础模式

```bash
# 所有 launch 命令添加 use_odom_fusion:=false
ros2 launch go1_bringup go1_nav.launch.py use_odom_fusion:=false
```

消融实验需要 robot_localization，此时无法进行融合对比实验。

### slam_toolbox 地图质量差 -> 使用 FAST-LIO2 PCD

```bash
# FAST-LIO2 会保存 PCD 点云
# 启动后会在 FAST_LIO/PCD/ 下生成 scans.pcd
pcl_viewer ~/go1_ws/src/FAST_LIO/PCD/scans.pcd
```
